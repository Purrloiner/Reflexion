PropaNews Zero-shot / Reflexion: 총 모델 호출 최대 3회, 정답 즉시 종료

사용자의 최신 요청에 따라 현재 기본 프로토콜은 정답이면 즉시 종료한다.
각 기사는 1차, 2차, 3차 추론까지만 허용한다. 별도 Reflexion 모델 호출은 없다.
기존 CoT 파일, llm.py, 이전 실험 결과는 수정하지 않는다.

1. 실행 흐름

- Zero-shot은 기사당 한 번만 분류한다. 이 응답이 Trial 1이다.
- Trial 1 정답: 즉시 종료. 총 모델 호출 1회.
- Trial 1 오답: 2차 호출 하나에서 이전 근거의 자기 성찰과 새 분류를 함께 생성한다.
- Trial 2 정답: 즉시 종료. 총 모델 호출 2회.
- Trial 2 오답: 3차 호출 하나에서 자기 성찰과 최종 분류를 함께 생성한다.
- Trial 3 정오와 무관하게 종료. 총 모델 호출 최대 3회. 4/5차 호출은 없다.
- 파싱/실행 오류는 오답으로 간주하지 않고 별도 기록하며 정상 완료로 세지 않는다.
- 실패/중단된 시도도 누적 한도 3회에 포함한다. 재시작/명시적 오류 재시도에서도
  한 기사에 4번째 호출이 나갈 수 없다. 한도 소진으로 미완료면 최종 평가를 생성하지 않는다.

2/3차 단일 응답 형식:
Reflection: 짧은 자기 성찰 (1~3문장)
Rationale: 짧은 새 분류 근거 (1~3문장)
Finish[real] 또는 Finish[fake]

다음 추론에는 최신 판단 근거에서 이전 분류를 제거한 텍스트만 입력한다.
장기 EPM이나 정답/정오 메시지는 넣지 않는다. 자기 성찰은 같은 응답에서 생성되어
해당 호출의 새 판단을 이끄는 구성이다. 독립적인 성찰 호출과 분류 호출로 나누지 않는다.

정답은 평가용 is_correct(index, prediction) 함수가 재시도 여부를 결정하는
데만 사용한다. 기사/근거/피드백을 만드는 함수에는 정답이나 정오 신호를
전달하지 않는다. 모델 프롬프트에 label, 원본 path, 이전 최종 분류는 없다.
단, 재시도 대상 선정 자체는 정답 정보를 사용하므로 평가 방식은 명시적으로
oracle/gold-gated early-stop 누적 평가다. label-free 고정 Trial 3 성능으로
표기하지 않는다. 기록된 누적 Accuracy는 Trial이 늘어도 감소하지 않는다.

4. 체크포인트와 캐시

checkpoint.sqlite3: 각 호출 직전 상태와 원본 응답을 SQLite WAL/FULL로 저장한다.
파싱 전 원본 응답을 commit하므로 중단 후 저장된 응답을 다시 생성하지 않는다.
정답 도달 여부는 같은 공식 정답과 저장된 예측으로 복원한다. 매 새 호출 직전에 SQLite의 해당 기사 전체 시도 수를 확인한다. 조기 종료
표시를 JSON에 쓰기 전에 중단돼도 정답 기사에 추가 호출하지 않는다.
기사별 JSON도 각 호출 뒤 atomic 저장한다. 동시 writer는 lock으로 막는다.

프롬프트/데이터/생성 설정/모델 파일/실행 환경/관련 소스 해시를 검증한다.
현재 통합 자기 성찰 프로토콜은 이전 고정 Trial/독립 Reflexion 호출 캐시와 호환되지 않는다.
이전 outputs/propanews_zeroshot_local 및 early_stop 결과는 보존하며 새 three_calls 경로를 쓴다.
기존 경로를 지정하면 provenance mismatch 오류를 내며 임의로 섞지 않는다.

parse_error는 원본을 보존하고 자동 재생성/임의 라벨 대체를 하지 않는다.
execution_error는 원인 해결 후 남은 총 호출 예산 안에서 --retry-errors로 명시 재시도할 수 있다.
호출 도중 중단된 uncertain 상태는 중복 방지를 위해 자동 재호출하지 않는다.
기록을 확인하고 --retry-uncertain을 지정하면 남은 총 호출 예산 안에서만 재시도한다.
OOM은 기존 함수로 캐시를 정리하고 다음 기사로 진행하되 완료로 취급하지 않는다.

5. 출력과 평가

manifest.json: schema_version=3, early_stop_on_correct=true, oracle_scoring=true,
max_total_model_calls_per_article=3, max_reflection_calls_per_article=0.
articles/000.json ~ 499.json: 기사별 상태와 실제 호출 결과.
records.partial.json / progress.json: 종료/중단 시 전체 상태.
errors.json / errors.csv: 파싱/실행 오류 및 불확실한 호출 이력.
dataset_validation.json: 원본 검증.

전체 500개 완료 시 results.json/csv, trial_summary.json/csv,
trial_transitions.csv를 생성한다. Trial 1은 Zero-shot, Trial 2/3은 정답 기반
조기 종료 정책을 적용한 누적 평가다. Accuracy, fake 기준 Precision/Recall/F1,
Macro-F1, Confusion Matrix, 수정 건수와 Trial 간 변화를 저장한다.
행=정답, 열=예측, 순서=[real,fake]로 [[TN,FP],[FN,TP]]를 사용한다.

실행하지 않은 Trial은 status=skipped_after_correct, executed=false,
prediction/response/reflexion_feedback/correct=null이다.
누적 평가에 유지하는 정답 예측은 effective_prediction/effective_correct에만
기록하며 carried_from_trial로 실제 출력 Trial을 연결한다.
success_trial과 stop_reason으로 종료 시점을 기록한다.
2/3차의 reflexion_feedback과 reflexion_response는 해당 분류와 같은 응답에서
생성한 자기 성찰이다. reflexion_call_id는 classification_call_id와 같은 호출을
가리킨다. 별도 reflect 레코드는 생성하지 않는다. total_model_calls로 실제
호출 수를 기록하며, 한도 소진 시 stop_reason=call_budget_exhausted가 된다.
final_prediction_source_trial은 마지막으로 사용한 실제 분류 Trial이다.

summary의 evaluation_mode=gold_gated_early_stop_cumulative와 oracle_scoring=true를
유지한다. executed_articles/carried_articles, solved_at_trial, cumulative_success로
실제 추가 호출과 유지된 정답을 구분한다. 조기 종료 때문에 한 번 맞힌 예측이
다음 Trial에서 틀리는 회귀는 발생하지 않으므로 correct_to_wrong은 0이다.
